# AIM-agent — протокол изменений и проверок от 22.11.2026

## Контекст и принципы

Задача: выполнить приоритетные исправления по результатам шести технических и шести рыночных проходов, записать каждую доработку и провести не менее четырёх независимых запусков тестов. Работа ведётся на ветке `feat/harden-audit-pipeline-v024`, `main` обновляется только после CI.

Сканы коммерческих сайтов и анализ их законодательства **не** служат доказательством соответствия. HTTP 401/403 — ограничение доступа нашему клиенту, а не SEO-проблема сайта.

## Протокол тестирования

`pytest` запускается четырьмя **отдельными полными** заданиями матрицы CI, а не одним запуском, результат которого умножен на четыре:

- Проход 1: Python 3.11, PYTHONHASHSEED=11
- Проход 2: Python 3.12, PYTHONHASHSEED=22
- Проход 3: Python 3.13, PYTHONHASHSEED=33
- Проход 4: Python 3.12, PYTHONHASHSEED=44

Каждый проход также выполняет `compileall` и `pip check`. Проверено по **четырём разным GitHub Actions job log**: все четыре завершены статусом success; **59/59 тестов успешно в каждом (236 успешных выполнений суммарно)**, `compileall` выполнен, `pip check` в каждом случае сообщил «No broken requirements found». Единственное предупреждение — библиотечный deprecation warning от Starlette/httpx. [Результат GitHub Actions](https://github.com/838DmitriyButrov/AIM-agent/actions/runs/44961179824).

Отдельно на Railway развёрнут приватный сервис `aim-v024-staging-verify` (Docker build и /health = SUCCESS) и выполнен одноразовый `aim-v024-live-smoke` на той же версии кода: `BENCHMARK_START` → три `SCAN_RESULT` → `BENCHMARK_DONE`. Все операции GET-only, не более трёх HTML-страниц на сайт, без браузера и LLM. МЕТРО: 3 страницы, 9 записей (квалификация требует отдельной проверки); Лента: 0 страниц, HTTP 401, `blocked_http`; Ашан: 0 страниц, HTTP 401, `blocked_http`. Ни один HTTP 401 не интерпретирован как правонарушение или SEO-дефект. [Архив Railway smoke](../reports/v024-railway-smoke-2026-11-21T2320Z.json). Эти проверки НЕ заменяют тесты на эталонном наборе сайтов.

## Что не закрыто этим релизом

1. **Production SSRF:** DNS preflight не обеспечивает защиту от DNS rebinding. Нужна network/egress isolation с контролем фактического адреса соединения. До неё публичный `/scan` не открывать.
2. **Credentials:** авторизация ограничена доменом, но отдельного vault и per-project isolation пока нет. Секреты не хранить в Git и не передавать чужим сайтам.
3. **LEGAL:** девять правил реестра всё ещё требуют проверки юристом; запрещены публичные юридические вердикты без такой проверки.
4. **GEO:** реальная видимость в ИИ-ответах не измеряется; нужны интеграции с подтверждёнными данными платформ и воспроизводимые промпты.
5. **UX:** не реализован. Нельзя обещать UX-аудит.
6. **Доказательный архив:** хеш HTML не равен воспроизводимому хранилищу; нужны маскирование персональных данных, срок хранения, доступ и история решений.
7. **Очереди и кластерные квоты:** semaphore ограничивает только один процесс; нужен отдельный job queue для production.
8. **Браузерная модель:** при блокировке внешних CDN не следует трактовать неполный DOM как дефект сайта. Playwright только для разрешённых владельцем проверок.
