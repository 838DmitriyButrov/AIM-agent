# Модель безопасности v0.2

Текущий инструмент рассчитан на **локальное использование**, а не на публичное API. Использовать только для разрешённых проверок.

**Что есть:** GET-only HTTP, same-host redirects, предварительная проверка IP по DNS, robots.txt, ограниченные таймауты/размеры ответов/число страниц/попыток, исключение нескольких потенциально state-changing GET-путей, нет отправки форм. Браузерный режим по флагу, без кликов и отправок. У cookies собираются только названия и домены, а не значения; значения полей ввода и паролей не копируются.

**Чего нет:** IP-pinning в момент соединения; от DNS rebinding код не защищён. Также отсутствуют полноценные SSRF-фильтрация на уровне сети, ограничение памяти/CPU контейнера, аутентификация публичного API, блокировка всех необычных GET-сценариев, защита от непредвиденных JavaScript side effects, rate limiting по клиентам. Поэтому `--browser` и сканирование чужих сервисов без разрешения недопустимы для коммерческого режима.

Рекомендуется отдельный egress proxy/firewall, который блокирует localhost, link-local, RFC1918, metadata IP и остальные непубличные адреса **на уровне фактического соединения**, без прямого сетевого обхода. Проверка схемы и DNS до запроса — лишь начальная защита.

Источники: [OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html), [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html).

**v0.2.1:** DNS-недоступность отделена от `UnsafeTarget`, добавлена диагностика `siteaudit doctor`. Её вывод не является разрешением обходить сетевые ограничения. Извлечение IP через DNS до HTTP-соединения не устраняет DNS rebinding, и произвольные HTTP(S)-прокси без сетевых правил использовать нельзя.
