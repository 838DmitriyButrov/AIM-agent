# Site Audit Agents — v0.2.4

**Рабочий исследовательский прототип** двух аудиторов российских сайтов: **LEGAL** и **GEO/SEO** с акцентом на поисковые ИИ-системы. Третий **UX/UI** предусмотрен архитектурой, но пока не реализован.

> **Важное ограничение:** это система первичного выявления признаков и формирования проверяемых задач для специалистов, **не** юридический сертификатор и **не** инструмент прогнозирования позиций/цитирований в ИИ. Публичный API без дополнительной сетевой изоляции и авторизации запускать нельзя.

## Стабилизация и исправления безопасности (v0.2.4)

- **robots.txt:** бот идентифицируется явным `SiteAuditAgents`; правила для собственного User-Agent соблюдаются. Не выдаём Python-сканер за Chrome.
- **HTTP:** убрано объявление Brotli без декодера; запросы `robots.txt`/`sitemap.xml` не получают авторизационных заголовков.
- **Учётные данные:** `SITEAUDIT_AUTH` отправляется **только** при явном `SITEAUDIT_AUTH_HOST` и строго на этот хост, не через редирект к другому домену. Использовать только при разрешении владельца.
- **URL:** безопасные функциональные query-параметры каталога сохраняются, трекинговые и неизвестные параметры отбрасываются; это намеренно ограниченная, а не полная поддержка query-URL.
- **GEO:** `noindex` и `nosnippet` для конкретного бота не обобщаются на все поисковые системы.
- **Отчёт:** записи `not_tested` выделены в отдельный раздел и не выдаются за подтверждённые дефекты. Обход, полностью запрещённый `robots.txt`, получает `blocked_robots`.
- **Приватный API:** разрешён только один одновременный аудит на экземпляр. При занятости отвечает HTTP 429.
- **Регрессии:** обязательный CI прогоняет **полный набор тестов четыре раза** на Python 3.11, 3.12 (дважды) и 3.13.
- Журнал разработки и оставшиеся ограничения: [docs/IMPLEMENTATION_LOG_2026-11-22.md](docs/IMPLEMENTATION_LOG_2026-11-22.md).

Публичный доступ по-прежнему не разрешён: проверка DNS до запроса не заменяет outbound egress firewall и защиту от SSRF.

## Диагностика сети и DNS (исправление v0.2.1)

Если внешний аудит завершается `DNS_TEMPORARY`, сначала запустите:

```bash
siteaudit doctor https://lenta.com/
siteaudit doctor https://metro-cc.ru/ --json
```

Команда отдельно проверяет DNS и прямой исходящий TCP, не запрашивает страницы. При блокировке DNS обычный `siteaudit scan` теперь **не падает без отчёта**: записывает JSON и Markdown с `scan_status=blocked_network`, `error_code=DNS_TEMPORARY` и нулём обследованных страниц; юридические/SEO-выводы не выдумываются. Код завершения `2` означает, что аудит не выполнен. Проблема может быть в сетевой политике среды; код не способен снять инфраструктурный запрет. Подробнее: [docs/NETWORK_TROUBLESHOOTING.md](docs/NETWORK_TROUBLESHOOTING.md).

## HTTP 401/403 и безопасная диагностика (v0.2.2+)

- Отчёты отличают `blocked_http` и `rate_limited` от SEO/LEGAL-находок; при отсутствии HTML не выдумываются недостатки сайта.
- Сохраняются только безопасные метаданные ответа (без cookies, тела HTML и auth-токенов).
- Опциональный браузерный режим проверяет JS H1 и ограничивает внешние запросы, но не является обходом антибот-защиты.
- Приватный `/scan` защищён токеном и allowlist; публичный доступ без egress firewall запрещён.
- [Подробный разбор HTTP отказов и действий](docs/HTTP_ACCESS.md).

## Как читать отчёт

Markdown начинается с охвата проверки и последствий, которые стоит учитывать. Для каждого замечания показано, что увидел агент, на что это может влиять и что проверить дальше. Одинаковые наблюдения объединены, а адреса страниц сохранены. Ограничения обхода и непроверенные пункты вынесены отдельно. Формат JSON с кодами правил, доказательствами и диагностикой сохранён.

## Быстрый старт (Python 3.11+)

```bash
cd site-audit-agents
python -m venv .venv
source .venv/bin/activate                 # Windows: .venv\Scripts\activate
pip install -e '.[test]'
python -m pytest -q
siteaudit scan https://example.com --max-pages 8 --out reports/demo
```

В результате появляются `reports/demo.json` и `reports/demo.md`. По умолчанию только публичные HTML-страницы в рамках начального хоста, GET, с учётом robots.txt; никакие формы не отправляются.

### Опциональная аутентификация

```bash
export SITEAUDIT_AUTH_HOST='staging.example.com' # строго тот же хост, которому принадлежит токен
export SITEAUDIT_AUTH='Bearer YOUR_TOKEN'   # или Basic base64(...)
siteaudit scan https://staging.example.com --max-pages 10
```

### LEGAL только

```bash
siteaudit scan https://example.com --agent legal --out reports/legal
```

### GEO/SEO и целевые запросы

```bash
siteaudit scan https://example.com --agent geo \
  --query 'Как выбрать CRM для малого бизнеса?' \
  --query 'Сколько стоит внедрение CRM?' \
  --out reports/geo
```

Важное отличие: `--query` **не ищет** сайт в Алисе AI или Google. Это только предварительное лексическое сопоставление вопроса с текстом обследованных страниц. Если релевантность нужно оценить семантически, можно дополнительно включить опциональную проверку LLM, результаты которой требуют проверки человеком.

### Браузерный режим — только при наличии разрешения владельца

```bash
pip install -e '.[browser]'
python -m playwright install chromium
siteaudit scan https://your-authorized-website.example --browser
```

Собираются имена и домены cookies до взаимодействия, завершённые сетевые запросы и количество символов после рендеринга первой страницы. **Не** проверяются accept/reject, отправки форм, логины, внутренние сервисы, реальные базы данных.

### Опциональный ИИ-анализ публичного контента

```bash
pip install -e '.[ai]'
export OPENAI_API_KEY='YOUR_KEY'
siteaudit scan https://example.com --agent geo --ai --query 'Как выбрать CRM?'
```

Использование `--ai` явно передаёт выбранные публичные выдержки страниц стороннему API. Содержимое сайта считается недоверенным, ИИ не может подтверждать правонарушения.

### Локальный API для разработки

```bash
pip install -e '.[api]'
uvicorn siteaudit.api:app --host 127.0.0.1 --port 8000
```

Эта версия API **не предназначена для публичного хостинга**. Предварительная DNS-проверка не исключает DNS rebinding и SSRF. Нужны сетевой egress-proxy, аутентификация, ограничения запросов и права на аудит. Подробнее: [docs/SECURITY.md](docs/SECURITY.md).

## Пределы того, что проверено

- **Локальные тесты:** см. CI в GitHub.
- **Сборка wheel:** проверена; встроенный реестр юрправил включён в пакет.
- **Проверки реальных сайтов:** зависят от сетевого окружения. При блокировке сохраняются структурированные нулевые отчёты.
- **Нормативная база:** начальный реестр на 22.11.2026, *не полная профессионально верифицированная правовая система*.
- **Индекс/ИИ-выдача:** не измерены. Отчёты Яндекс Вебмастера требуют доступа, подтверждающего права на конкретный сайт.

Следующий технический этап — защищённый запуск на разрешённом тестовом домене, расширенная верификация юридических документов и интеграции с данными Вебмастера. Приоритет развития: [docs/ROADMAP.md](docs/ROADMAP.md).
